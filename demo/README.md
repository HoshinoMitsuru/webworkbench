## 2. 三个 Demo 的共同演示边界

1. **生成是模拟的**：本地模板 + 变量替换，不调用大模型。界面上有"演示模式"标注。演示的是**流程与产物形态**，不是最终文案质量。
2. **数据是虚构的**：活动记录、主理人姓名、学员反馈均为示例，界面标注"示例数据"。真实公开数据（如 10 月 27 场、690 余人、一日职业体验评分 9.02）仅作背景引用，注明来源。
3. **事实锁定**：人数、场次、金额、评分等数字只能来自结构化输入，模板中不允许模型改写 —— 这是慈善组织信息披露的硬约束（画像文档 §8）。
4. **授权拦截**：素材未标"已授权可公开"就不进生成环节（D1 里可以现场演示这个拦截）。
5. **人工审核位**：所有产物默认"草稿"，需要人点"通过"才进入"可发布"。AI 是初稿位，不是发布位。
6. **零学习成本导向**：表单字段刻意对齐机构已有的"十月刊"格式（活动名｜主理人｜时间｜人数｜坐标｜细节），不要求机构先学一套新系统。

## 4. 对谈时怎么用（建议动线，共 8–10 分钟）

1. **先问后演**：先用提问稿把现状问完，再开 Demo —— 避免"我们演示完他只剩附和"。
2. **D1 走一遍完整链路**（4 分钟）：填一行活动 → 点生成 → 切五个产物页签 → 指给他看"这就是你们十月刊的格式，只是前移到了活动当天"。现场把"素材授权"关掉再生成一次，看拦截提示。
3. **D2 只讲一个点**（2 分钟）：数字全部来自台账、模板不产数字。问他"各项目愿不愿意活动当天记一行"——这是候选 B 的前置条件，他的回答决定 A/B 优先级。
4. **D3 用来验证 P8**（2 分钟）：先问"青桥从报名到匹配要多久？等待期发东西吗？"再展示。若 P8 被推翻，当场划掉，这个 Demo 就不进需求文档。
5. **收尾逼优先级**："这三个里，如果四周只做一个，您选哪个？"

## 5. 已知缺口（诚实标注）

- 机构真实需求原文尚未取得（画像文档 §附录"未获取信息"），三个 Demo 是**基于公开证据的预猜**。
- D1 的"机构知识库/话术约束"仅以三种项目线口吻示例呈现，正式版本需要机构提供 2–3 篇标杆稿做语料。
- D3 的等待天数、批次节奏全部虚构，青桥真实匹配周期未知。
- 海报仅输出"文案 + 版式建议"，不出成图；成图能力（W5）作为二期加分项口头介绍即可。
