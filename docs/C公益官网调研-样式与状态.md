# C公益官网调研：样式与状态

> 用途：2026-11-13 机构进组沟通前的预研补充，配合《C公益-机构画像与需求预研.md》使用
> 调研时间：2026-11-13｜调研对象：www.cyouthchange.org（含 12 个导航页、月报合集、捐赠链路）
> 证据分级：**【确证】** 本次实测/页面原文｜**【推断】** 基于证据的推论，需当面核实

---

## 0. 一句话结论

官网不是内容运营阵地，而是**公信力与合规背书页**：2026 年 7 月刚换完 Logo 3.0，但只换了首屏轮播和标识，正文仍是旧模板；月报、财务公示、审计报告等"可信内容"很全，但**入口分散、阅读链路有断点**（71 份月报是飞书文件，未登录只能看第 1 页）。这决定了我们**不要把"官网改版"当 MVP**，而应把官网当作三件事的证据来源：①品牌 3.0 尚未落地到模板；②内容"一次生产、多端分发"缺位；③机构对"工具迁移"高度敏感（2026 年上半年刚经历灵析停服、月报从飞书搬到公众号）。

## 1. 技术底座与运行状态【确证】

| 项目 | 实测结果 | 含义 |
|---|---|---|
| 建站方式 | **Strikingly（上线了 sxl.cn）**，响应头 `Strikingly-Cache`，静态资源在 `sxlcdn.com` | 无技术团队也能改；但无 API、无自定义内容模型，"系统级改造"做不了 |
| 访问 | HTTP/HTTPS 均 200，TTFB 约 240–310ms；证书正常 | 国内访问正常 |
| 首页体积 | HTML 224KB；17 张独立图片合计 **5.1MB**，全部 PNG（含 4 张 2813×1197 轮播图） | 图片未压缩/未转 WebP，移动端流量成本高 |
| 移动端 | 有 viewport、有响应式断点、汉堡菜单正常；但首屏轮播出现**横向溢出/裁切**（截图中卡片左侧文案被截断、右侧留白） | 移动端可用，但首屏不精致，需真机复核 |
| 字体 | Noto Sans SC + Montserrat（Google Fonts CDN） | 中文正文用 Noto Sans，标题无衬线粗体 |
| 页面规模 | sitemap 46 个 URL，导航只暴露 12 个 | 34 个历史/隐藏页仍在发布，存在过期信息风险 |
| SEO/基础 | 有 canonical、OG、sitemap.xml、robots.txt；404 正常；无站内搜索 | 基础合格，但不做内容运营 |
| 合规标识 | 页脚有宁 ICP 备 17000474 号-1、宁公网安备 64010402000810 | 齐全 |

**判断**：官网的"技术状态"是健康的，问题不在能不能打开，而在**内容与视觉的维护质量**。

## 2. 视觉样式：两套品牌系统并存

### 2.1 2026 新品牌（Logo 3.0，2026-07-16 发布）

从 Logo 与首页 4 张轮播图取色【确证】：

| 角色 | 色值 | 用法 |
|---|---|---|
| 天蓝 | `#79D3F2` | 首屏大背景 |
| 奶油白 | `#FAF7E8` | 轮播卡片底 |
| 品牌橙 | `#FC9B00` | Logo 外环、胶囊按钮 |
| 深棕 | `#5A2D0C` | 标题字、Logo 字标 |
| 嫩绿 | 约 `#9BD500` | Logo 新芽 |

- Logo 3.0：橙色 C 环 + 蓝色 C 环 + 破土新芽，字标为深棕圆体；口号「向下扎根，向上生长」。
- 首屏版式：天蓝底 + 奶油色大圆角卡片 + 左侧证书/现场照片 + 右侧衬线感棕色标题 + 橙色胶囊按钮（"点击查看"/"扫码了解更多"）。
- 首屏 4 张轮播主题**全部是资质类**：小程序上线、业务范围变更、公募资格、4A 评级。官网第一屏在说"我们可信"，而不是"我们为青年做了什么"。

### 2.2 旧模板（正文各页仍在用）

- 白底 + 橙色 `#FBB23C / #E8A336` + 深色 `#191001 / #222222`。
- 40px Noto Sans 粗标题、全幅活动现场照片 + 深色蒙层 + 白色大字（/8 捐赠页最典型）。
- 标题层级混乱：首页出现 6 个 `h1`，正文大量用 `h4`；轮播文案烘焙在 PNG 里，不可检索、改一句话就要重做图。

### 2.3 风格判断

- 关键词：**温暖、年轻、去机构化、真实照片优先**；人物出镜多、插画少、留白大、信息密度低。
- 新品牌方向是"蓝天 + 土壤 + 种子"的生长叙事，和机构"朋辈陪伴"的调性一致。
- 主要问题不是丑，而是**不统一、不可复用**：新品牌只覆盖了首屏，正文仍是旧橙色模板；没有可交给志愿者的版式规范。

> 对我们的直接含义：如果做生成工具，**输出物必须自带品牌 3.0 的色板、字号、圆角、按钮样式**，并且能出多尺寸封面图；否则只是把"手工排版"换成"手工改 AI 稿"。

## 3. 内容与更新状态

### 3.1 导航与内容盘子【确证】

12 个导航页：首页 / 了解我们 / 公益周边 / 支持我们 / 大学生板块 / 志夏青年 / 职场青年板块 / 探索者计划 / 过往项目 / 公开透明 / 研究及评估报告 / 机构动态。

- **机构动态**仅 12 条，最新一条 **2026-07-18**（距调研日约 4 个月）；内容混合党建、重大事项披露、Logo 发布、年度报告、媒体报道、受益人故事。
- **月报合集 /16** 有 **77 条**月报链接（71 条飞书文件 + 6 条公众号），覆盖 2020–2026；2026 年 1–10 月**齐全**。
- **公开透明 /2** 只列到 2026 年 7 月月报 → 与 /16 口径不一致。
- 2026 年月报渠道在 5 月发生切换：1–4 月是飞书 PDF，5–10 月是公众号推文【确证】。
- 财务公示存在**重复链接**：2024 与 2025 年财务公示指向同一篇；第一期与第二期财务公示也指向同一篇【确证】。
- 审计报告 2020–2025、年检 2021–2024、章程、10 项制度、登记/资质证书齐全【确证】。

### 3.2 公开内容的实际可读性（关键发现）【确证】

抽查 2026 年 1 月月报飞书链接：未登录状态只能看到 **第 1 页 / 共 25 页**，页面提示「没有权限访问 暂无权限查看文件信息」，并有「登录/注册」按钮。

也就是说：**官网"公开透明"栏目里 71 份月报，对普通访客实际上是不可完整阅读的**。这不一定违反慈善组织信息公开的硬性要求（年报/审计/年检齐全），但与"公开透明"的对外表达有落差。

### 3.3 更新节奏判断

- 官网的真实节奏：**每月 1 次月报 + 不定期公告**，日常活动内容几乎不上官网。
- 公众号才是主阵地（10 月单月 27 场活动、月报、招募），官网承担的是"留档 + 背书 + 给合作方/政府/捐赠人看"。
- 【推断】2026 年上半年机构在做一轮工具迁移：灵析 4 月 30 日停服、月报 5 月从飞书转公众号。此时给他们塞一个"新系统"，阻力会比平时更大。

## 4. 捐赠与转化链路【确证】

/8「支持我们」是 4 张全幅照片卡片，均可点击：

| 入口 | 去向 | 状态 |
|---|---|---|
| 单笔捐（≤5 万） | 腾讯公益乐捐项目页 `gongyi.qq.com/succor/detail.htm?id=3020540` | 200 可用 |
| 月捐（15–500 元/月） | 易宝公益 H5 `mp.yeepay.com/0/h9ILLkLruaI` | 200 可用 |
| 大额捐（>5 万） | 飞书表单 | 200 可用 |
| 月捐大使 / 年捐 | 飞书表单 | 200 可用 |

**但存在一处明显不一致**：/2 公告写明「灵析平台已于 2026-04-30 停服，捐赠查询改用飞书」，而**首页「捐赠查询」仍在嵌入灵析的 `gongshi.lingxi360.com` 公示 iframe**。是漏改还是仍在用，需当面确认。

工具栈全景：Strikingly + 微信公众号 + 飞书（文件/表单/多维表格）+ 灵析（停用中）+ 易宝 + 腾讯公益 + 135/秀米/可画。**出口多、系统散、没有统一内容中台**——这既是我们机会，也是我们必须避免"再加一个孤岛"的原因。

## 5. 对方可能提出的需求：预判与应对

按可能性排序，现场听到时可直接对照：

| # | 可能的需求 | 可能性 | 证据 | 我们的应对 |
|---|---|---|---|---|
| W1 | 「能不能帮我们重做/更新官网」 | 中高 | 新旧视觉混用、移动端首屏溢出、重复链接、灵析入口未撤 | **不接重建**。官网是 Strikingly，他们自己能改；一年只更新 12 次，重建 ROI 低。可承诺"给一套官网更新清单/模板"，把重建挡在 MVP 之外 |
| W2 | 「品牌 3.0 落不到公众号/小红书/海报上」 | 高 | 官网仅首屏换新；排版岗 1 人；工具是可画/Canva 手作 | 这是我们"模板 + 品牌规范"的最佳切入点，可作为活动成稿的加分项 |
| W3 | 「月报、财务公示、年度报告能不能自动写」 | 中高 | 77 份月报、固定栏目、跨项目汇总；重复链接说明人工维护易错 | 可做"结构化数据 + 固定模板 + 人工复核"，但**必须锁数字**，不能纯生成；适合二期 |
| W4 | 「把月报/动态搬到官网，别再用飞书」 | 中 | 飞书限权、两处口径不一致、5 月起已改公众号 | 技术上可做"月报一键转长图/网页"，但 Strikingly 无 API，只能人工粘贴；先问清优先级 |
| W5 | 「封面图/海报批量做，还要压小」 | 中 | 首页 5.1MB PNG、4 张 2813×1197、文字烘焙进图 | 最容易被低估、最立竿见影；可作为 demo 的"顺手能力"，不单独做产品 |
| W6 | 「一次生产，多平台分发」 | 高 | 小红书专岗、官网低频、公众号高频 | 这是主叙事，但**重点说公众号 + 小红书**，不要把官网当主场景 |
| W7 | 「官网 SEO / 拉流量 / 在线捐赠优化」 | 低 | 无投放、无流量考核证据 | 不主动提；若对方提，先问"你们看访问数据吗" |

**三条硬约束**（写进需求文档时直接用）：

1. 不做官网重建，不做通用写作工具；
2. 输出必须能进 135/秀米，或直接生成可粘贴的图文，不增加一道工序；
3. 涉及金额、人数、备案号的内容必须锁定事实，不能交给模型自由生成。

## 6. 对谈时可补的 5 个官网问题

现有提问稿偏内容流程，这 5 个问题专门验证官网相关假设，按时间余量选问：

1. 官网现在谁维护？7 月换 Logo 3.0 时，为什么正文页没有一起换？
2. 月报为什么有的放飞书、有的放公众号？知道飞书链接未登录只能看第 1 页吗？
3. 官网的访问量/来源你们看吗？它主要给谁看——捐赠人、合作方、政府，还是学生？
4. 首页「捐赠查询」还挂着灵析，但公告说 4 月已停服，是漏改还是仍在用？
5. 如果我们做内容工具，你们希望它跟官网发生关系吗？还是只管公众号和小红书？

**现场可讲的一句判断**（用于建立专业感，不评判）：

> "我们看了官网，感觉它更像机构的'可信度档案'，不是日常内容阵地；真正的内容压力在公众号和小红书。所以我们不会建议重做官网，而是想让一次生产能同时喂饱这几个出口。"
