# C公益 AI 内容工作台 · 一键发布可行性调研

- 日期：2026-11-24
- 检索范围：微信公众号、视频号、小红书、抖音、微博的公开开放平台能力与发布规范
- 结论适用范围：当前工作台（Next.js + SQLite，无角色权限分级），发布默认由工作人员手动完成

---

## 一、结论摘要

1. **不建议把“一键发布”做成默认能力。** 只有微信公众号存在面向认证主体的公开“发布草稿”接口，且发布是异步任务、仍可能因原创/平台审核失败；视频号、小红书没有对第三方开放的发布接口；抖音仅对特定企业主体和特定应用类型开放，且明确不向营销类内容开放。
2. **推荐路径排序**：
   - **默认（已实现）**：工作人员在平台手动发布 → 回工作台记录发布结果，发布记录默认勾选“已在平台完成 AI 声明”，隐式元数据始终保留。
   - **下一步可选（低风险）**：公众号“保存到草稿箱”半自动。工作台只把审核通过的图文同步为草稿，由工作人员在公众号后台确认后手动点发布。
   - **谨慎评估**：公众号 `freepublish/submit` 直接发布。需认证服务号、接口凭据、服务器 IP 白名单、回调域名与失败处理。
   - **不做**：用浏览器自动化模拟点击发布小红书/视频号/抖音。违反平台规则风险高，易触发风控、限流或封号，也无法稳定留痕。
3. **若未来提供“一键发布”入口，必须同时满足**：
   - 只在内容 `approved` 后出现；
   - 首次使用展示能力边界与失败可能；
   - “含 AI 生成内容声明”默认勾选且不可静默取消；
   - 记录操作人、时间、平台返回 ID、失败原因，并写入审计；
   - 敏感/未成年人相关内容默认保留显式 AI 标识，不因“一键”而跳过审核。

## 三、关键平台事实与来源

### 3.1 微信公众号：唯一可落地的官方路径

- `freepublish/submit` 用于把**已保存的图文草稿**提交发布，请求体只需草稿 `media_id`，`access_token` 放在 Query。
- 适用范围写明“仅认证”：只允许**企业主体已认证账号**调用；并注明 **2025 年 7 月起，个人主体账号、企业主体未认证账号及不支持认证的账号将被回收调用权限**。
- 返回 `publish_id` 只表示**发布任务提交成功**，不代表发布完成；最终结果通过开发者 URL 的 `PUBLISHJOBFINISH` 事件推送，`publish_status` 可能为原创失败、常规失败、平台审核不通过等。
- 调用前需要在公众平台配置服务器 **IP 白名单**并获取 `access_token`；草稿接口还需要标题、作者、正文、封面 `thumb_media_id` 等字段。
- 因此：如果机构公众号是**认证服务号**，可做“存草稿箱 → 人工确认发布”；如果是订阅号/个人主体/未认证，接口不可用。

来源：
- [发布草稿 freepublish/submit](https://developers.weixin.qq.com/doc/subscription/api/public/api_freepublish_submit.html)
- [发布能力（服务号指南）](https://developers.weixin.qq.com/doc/service/guide/product/publish.html)
- [新增草稿 draft/add](https://developers.weixin.qq.com/doc/service/api/draftbox/draftmanage/api_draft_add.html)

### 3.2 视频号：没有开放发布接口

- 微信开放社区答复明确：“发布视频号视频的官方 API 目前尚未开放”，建议使用视频号助手等官方工具管理内容。
- 市面上的“视频号自动发布”工具，底层是模拟真人在创作者后台操作（浏览器自动化），不是官方接口。

来源：
- [视频号交流专区答复](https://developers.weixin.qq.com/community/minihome/question/1807982532018110467?page=7&tag=new)
- [视频号自动发布原理说明](https://www.publishport.app/zh/blog/weixin-channels-auto-publish)

### 3.3 小红书：开放平台不提供笔记发布

- 小红书开放平台的应用类目与权限以商家经营、电商服务为主，未提供面向普通开发者的笔记发布接口。
- 第三方“一键分发”通常依赖账号授权或浏览器自动化，稳定性和合规性都无法保证。

来源：
- [小红书开放平台 API 文档](https://xiaohongshu.apifox.cn/)
- [小红书开放平台](https://open.xiaohongshu.com/)
- [开放平台 API 接入实操（资质与边界）](https://news.sohu.com/a/1097422460_121744364)

### 3.4 抖音：门槛高且明确排除营销场景

- 抖音开放平台 2025-08-19 通知：发布内容至抖音能力**不再向个体工商户开放**；企业主体需**注册资本≥50 万且注册时间≥1 年**；仅对**创作工具、社区、硬件配套、游戏类**正式应用开放；仅面向 **C 端用户创作后分享**，企业宣传、商品介绍、诱导分享等营销类内容不开放；长期不调用会回收能力。
- 这意味着公益机构的日常招募/回顾宣传，通常不符合其开放场景。

来源：
- [发布内容至抖音能力回收 & 开放规范调整通知](https://developer.open-douyin.com/announcement/348)
- [抖音发布 & 转发能力使用规范](https://developer.open-douyin.com/docs/resource/zh-CN/dop/operation-standard/platform-capabilities/useclue)

### 3.5 合规要求：AI 标识不能因“一键”而省略

- 《人工智能生成合成内容标识办法》要求对 AI 生成合成内容添加**显式标识**（用户可感知）与**隐式标识**（文件元数据等）。
- 平台侧也在强化声明：微信公众号曾公告要求创作者对 AI 生成内容进行标识/声明。
- 工作台当前策略：审核通过只免“显式”标注；PNG 隐式元数据、审核记录、发布记录始终保留；发布时默认勾选“已在平台完成 AI 声明”。

来源：
- [《人工智能生成合成内容标识办法》](https://www.gov.cn/zhengce/zhengceku/202503/content_7014286.htm)
- [微信关于 AI 生成内容标识的公告](https://developers.weixin.qq.com/community/develop/doc/000ce4a4234cb8bee4c3d28436b009)

## 四、如果做“一键发布”，产品上必须怎么设计

### 4.1 入口与提示

- 仅在内容状态为 `approved` 时显示。
- 入口旁明确标注能力边界，例如：
  - “公众号一键发布：需认证服务号并完成接口配置；发布为异步任务，可能因原创/平台审核失败。”
  - “小红书/视频号：平台未开放发布接口，请手动发布后回填记录。”
- 首次点击弹出确认，说明“不会跳过审核”“失败会留痕”，避免工作人员误以为发布必然成功。

### 4.2 AI 声明

- 发布确认框中“已在平台完成 AI 生成内容声明”**默认勾选**。
- 若平台无对应声明选项，要求保留隐式元数据并在备注说明，发布记录标记“未声明 AI”，便于事后追溯。
- 隐式元数据（`DigitalSourceType=trainedAlgorithmicMedia`、内容/活动/任务 ID、生成时间）在导出文件中始终保留，审核通过不清除。

### 4.3 留痕与失败处理

- 保存平台返回的 `publish_id` / `article_id` / 失败原因；公众号异步结果通过回调或定时查询补写发布记录。
- 发布失败不自动重试，给出“重新发布/改为手动发布”两个选项。
- 审计记录包含：操作人、时间、平台、声明状态、结果。

### 4.4 凭据与安全

- `app_id` / `app_secret` / `access_token` 只存服务端，前端不可见；数据库中加密或使用环境变量。
- 服务器出口 IP 固定并加入公众号 IP 白名单；`access_token` 缓存并处理过期。
- 回调 URL 使用 HTTPS，并校验签名/来源。

### 4.5 权限与责任

- 当前项目不做角色权限分级，因此“一键发布”至少要求二次确认，并在发布记录中体现操作人。
- 涉及未成年人、肖像、资助方标识的内容，建议强制保留显式 AI 标识，且不允许一键发布跳过人工复核。

## 五、建议路线

| 阶段 | 内容 | 前置条件 | 风险 |
| --- | --- | --- | --- |
| P0（已实现） | 人工发布 + 回填记录；发布记录默认“已声明 AI”；审核需勾选“知悉含 AI”；PNG 隐式元数据增强 | 无 | 低 |
| P1（建议评估） | 公众号“同步到草稿箱”：只建草稿，不直接发布 | 认证服务号、`app_id/app_secret`、IP 白名单 | 低-中，失败不影响线上 |
| P2（谨慎） | 公众号 `freepublish/submit` 直接发布 + 回调补写结果 | P1 全部条件 + 回调域名 + 运维值守 | 中，存在异步失败与审核不通过 |
| 不做 | 小红书/视频号/抖音浏览器自动化发布 | — | 高，封号与合规风险 |

**建议先做 P1**：它能让工作人员少一次复制粘贴，又不把“发布成功”的责任交给系统。等公众号侧接口稳定运行一段时间，再评估是否开放 P2。

## 六、工作台当前落地情况（2026-11-24）

- `reviews.ai_ack`：审核通过时必须勾选“已核对事实、数据与授权，并知悉含 AI”，否则前后端都拒绝通过。
- `publish_records.ai_declared`：发布记录保存“是否已在平台声明 AI”，界面默认勾选，记录列表显示“已声明 AI / 未声明 AI”。
- 审核弹窗/详情区新增“本内容含 AI 生成成分”提醒；审核记录显示“已确认含 AI”。
- 发布表单增加“发布方式：人工发布（推荐）”说明，并注明公众号一键发布需资质与配置、当前未启用。
- PNG 导出元数据增加 `DigitalSourceType`、`AIGeneratedAt`、`AIContentID`、`AIActivityID`、`AITaskID`，保留 `Software` 与 `Comment`。

## 七、待机构确认

1. 机构公众号的主体类型与认证状态（服务号/订阅号、企业/个人）。若不是认证服务号，P1/P2 都不可行。
2. 是否愿意提供公众号 `app_id/app_secret` 并配置服务器 IP 白名单与回调域名。
3. 发布失败时由谁处理（运营手动重发 vs 技术排查），是否需要站内提醒。
4. 是否需要在发布记录中回填阅读/报名转化数据（与 G-17 相关）。
