## 0. 结论摘要

C公益 的内容生产需求是**真实、具体、且已被机构自己写成文档**的：围绕「一份活动资料 → 多平台多形式传播内容」，覆盖文案、图文视觉、视频脚本三个方向，并按 P0/P1/P2 排了序。

本轮澄清新增了四条决定性信息：

1. **真实链路已经清楚**：项目部出方案与素材 → 新媒体部门统一审核与制作发布 → 公众号 / 小红书 / 视频三条出口，而机构对接本项目的新媒体负责人只有陈诗瑶一人（实际团队规模待确认）。
2. **机构的真实卡点不是"不会写"，而是"信息每次都要重新给"**：数据都在飞书，但没有数据库接入智能体，每次任务都要单独提供信息（郎鹏原话）。
3. **落点已基本锁定在飞书**：能搭载飞书就搭载飞书，否则做内部网页工作台；模型与费用由火山引擎公益计划兜底，不构成约束。
4. **时间受限时的优先级与文档 P0 不完全一致**：文档 P0 文案在前，口头答复是"时间紧就先做海报 + 小红书笔记封面"。这是需要组内拍板的第一决策点。

一句话：**需求不缺，缺的是把"品牌规范 + 历史素材 + 活动资料"变成一次输入、多出口生成的底座，而不是再做一个通用写作工具。**

## 2. 官方需求原文要点

来源：C公益 AI 内容生产应用需求（飞书 wiki，2026-11-16 发布）

### 2.1 总目标【文档明示】

围绕**文字内容生产、图文视觉设计、视频脚本生成**三个方向建立 AI 辅助内容生产工作流。工作人员只需提供活动策划方案、项目资料或已有图文视频素材，即可生成适用于**公众号、小红书、抖音、视频号、微信社群**的内容，并可根据**学生、公众、媒体**等不同受众调整表达。

最终形态：从「输入一份活动资料」到「生成多平台、多形式传播内容」，减少重复劳动，同时保证**真实性、专业性、品牌一致性**。

### 2.2 三个方向的要点

| 方向 | 核心要求 |
|---|---|
| 文案 | 公众号招募/回顾推文、小红书笔记、新闻稿、朋友圈与社群话术、青年知识科普；同一份资料生成学生版/公众版/新闻稿三个受众版本；按活动阶段（招募前→正式招募→招募期→活动前→现场→结束→后续）成组产出 |
| 图文视觉 | 活动海报（**默认 3:4 竖版**，含预热/招募/倒计时/回顾四版）、小红书多图笔记（封面+正文页+行动页成套，5–7 张）、公众号封面与排版、PPT 与报告模板、长图/人物卡/日程图/邀请函等 |
| 视频脚本 | 1 分钟以内的活动招募、活动回顾、青年故事、知识科普脚本，含分镜、时长、画面、字幕；并推荐选题 |

### 2.3 共同能力（三方向共用底座）【文档明示】

资料理解｜内容提炼｜平台适配｜受众适配｜品牌规范｜模板复用｜素材调用｜局部编辑（只改某段/某张，不全部重做）｜内容审核（提醒核对事实、数据、人物授权、政策来源）｜文件导出（文字、高清图、短视频、可编辑 PPT）

文档特别提示：**AI 写文案、生成静态海报、剪辑现有视频、输出可编辑 PPT 是四种不同技术能力，未必能一个工具全包**，需求可按一体化工作流写，选型需分别验证。

### 2.4 官方优先级【文档明示】

| 优先级 | 需求 |
|---|---|
| **P0 必须实现** | 活动方案生成公众号招募/回顾推文｜生成小红书笔记及标题｜生成社群及朋友圈话术｜生成 3:4 活动海报与封面｜学生版/公众版/新闻稿转换 |
| **P1 重点实现** | 小红书多图内容自动拆页与设计｜根据素材生成 1 分钟内短视频｜自动字幕、BGM 调整、封面制作｜PPT 内容生成与可编辑模板 |
| **P2 逐步实现** | 青年科普自动选题及栏目化生产｜品牌素材库、模板库及多平台复用｜内容审核、数据跟踪及效果优化 |

## 3. 本轮澄清的事实（按来源可溯源）

### 3.1 真实内容生产链路与分工【机构确认｜陈诗瑶 11-18 16:20】

```
项目部：写活动方案 → 设置报名表单 → 写活动招募推文（推文中放报名链接）
      ↓ 招募学员 → 开展活动 → 志愿者现场拍摄照片 → 活动结束整理照片与文稿 → 写活动回顾推文
新媒体部：内容审核 → 最终制作发布
      ├─ ① 公众号：排版发布（最常用平台）
      ├─ ② 小红书：图文内容制作发布（按活动需求发布）
      └─ ③ 活动素材留存 → 后续梳理成视频
```

关键点：

- **项目部负责"内容事实"，新媒体部负责"审核 + 成稿 + 发布"**，两段之间是交接点，也是重复劳动的集中段。
- 机构指派对接本项目的新媒体负责人为陈诗瑶一人【机构确认，11-16 郎鹏介绍"诗瑶是我们机构的新媒体负责人"】；新媒体团队实际人数未答【待确认】。
- 这是一条**每场活动都要重走一遍**的流水线；10 月单月 27 场活动的量级可作负载参照【公开核实】。

### 3.2 平台策略【机构确认｜陈诗瑶 11-18】

- **公众号 = 主阵地**，最常发布。
- **小红书 = 按活动需求发布**，同时正在探索"内容营销"方向（公益科普、青年故事、活动反馈三类），目的是扩大机构影响力。
- 小红书有两个账号：机构内容账号、活动内容账号（链接已提供，见附录）。
- 视频：目前是"活动素材留存后另行梳理"，尚未形成固定产出节奏。

### 3.3 修改成本：对"排版瓶颈"假设的修正【机构确认｜陈诗瑶 11-18】

> 原话：临时更改报名时间后，公众号推文内容、小红书图文内容、社群转发话术都要改；**但一般会在活动内容都确定之后才发布，小细节改起来没有想象中那么耗时。**

这一条**下调**了预研中 P1"排版是瓶颈"的严重度判断：机构自己描述的多点同步修改成本是可接受的。真正的浪费更靠前——**同一份事实被反复重新组织成三种表达**，而不是改字本身。

### 3.4 使用形态：飞书优先【机构确认｜郎鹏 11-20 10:22 + 陈诗瑶 11-20 09:54】

- 郎鹏：**"如果可以优先能够搭载在飞书，就搭载在飞书；如果搭载在飞书的效果或使用方式受限，就采取 A（内部网页工作台）。"**
- 陈诗瑶：对最终形态**暂时没有明确偏好**。
- 结论：**飞书内嵌 / 飞书工作流为第一选择，内部网页工作台为退路；小程序、独立 App 不在优先序列。**

### 3.5 成本与模型：不构成约束【机构确认｜郎鹏 11-20 11:20】

> 原话："感谢火山引擎，我们有火山引擎的公益计划支持，他们的所有模型我们都可以用。"

因此预研中"无内容预算、优先免费方案"的约束**解除**。但需注意：可用 ≠ 已开通，落地前仍需确认账号与调用方式。

### 3.6 时间受限时的优先级（与 P0 的关系）【机构确认｜陈诗瑶 11-20 09:54】

- "优先级是按第一需求划分，可以按文档执行。"
- "**受时间限制的话，可优先完成海报、小红书笔记封面生成这个方向。**"
- 视频："**如果能实现 C（AI 直接生成完整视频）最好；暂时无法实现的情况下可实现 A（拍摄脚本）、B（剪辑脚本）。**"

→ **冲突点**：文档 P0 文案在前、视觉在后；口头兜底方案把视觉提到最前。这直接影响 MVP 切法，需组内拍板（见第 8 节）。

### 3.7 视觉与视频的输入条件【机构确认｜陈诗瑶 11-20】

- **品牌视觉规范 PDF**、**文案撰写规范 PDF** 已提供（见附录），可直接作为生成约束与评测基准。
- 参考账号可直接看机构小红书两个号，无需另行索取样本。
- 活动策划的选题逻辑：**活动大方向是既定的**（职业生涯体验、职业规划培训、1 对 1 咨询、社会实践支持等），在大方向下拆不同主题，再按主题选嘉宾。
- 嘉宾来源：内部资源与过往合作偏多，也会外部主动搜索。
- 对外展示成果的现有方式：① 公开资质 ② **年度报告**（每年一次，用于信息公开披露，并打印给合作方）③ 官网、介绍手册 PPT。

### 3.8 AI 使用现状与真实卡点【机构确认｜陈诗瑶 11-20 17:55 + 郎鹏 11-20 19:13】

机构当前的日常工具与 AI 现状：

| 项 | 现状 |
|---|---|
| 办公底座 | **飞书，覆盖所有岗位**；设计类用**可画**（海报、PPT） |
| AI 工具 | 人均不统一，**ChatGPT 居多**，也有豆包、DeepSeek；用途为设计、文案产出、数据分析、热点查询、海报制作 |
| Agent 认知 | 用过**扣子**；Skills、自定义智能体、专家团、知识库、连接器**均有初步接触**，但**机构内尚无成体系跑起来的应用** |
| 已跑出的三个真实场景 | ① 青年发动战略攻坚小组与主理人协作（需要"点子落地活动""社群运营能力""策划-宣发-执行-复盘工具支持"）→ 已落地**社群运营方法支持**与**活动方案热点推送** 2 个工具；② 会议纪要 → 做出【小会】，发录屏给智能体产出纪要（受飞书/豆包改制影响，改用豆包免费额度后使用频次下降，但需求仍在）；③ 新媒体视频剪辑 → 做出口播粗剪 Skill |
| **核心障碍（原话）** | **"核心是我们的数据都在飞书，但是没能建立起数据库接入智能体，所以每次任务解决可能都需要单独提供信息，互动的过程其实是更加耗时。"** |

这条是本轮最重要的一条需求证据：**机构要的不是又一个写作工具，而是"知识/素材可被智能体直接读取"的底座**。

### 3.9 集成度与自动化偏好（量化）【机构确认｜陈诗瑶 11-20 17:55】

| 维度 | 评分（0–10） | 含义 |
|---|---|---|
| 工具集成程度 | **8** | 希望尽可能在同一个平台内完成全部工作 |
| AI 自动化程度 | **9** | 希望 AI 按目标自动推进，人主要负责审核确认 |

人工必须保留的环节：**完整活动策划内容、内容发布、文字核对**。
希望 AI 自动完成的：**文案撰写、海报设计、图片生成、活动方案提议**。

### 3.10 活动策划的真实难点【机构确认｜郎鹏 11-20 19:18】

郎鹏把活动策划最核心的问题归为两点：

1. **流程设计**：怎么让活动流程与参与者有交互、能吸引注意力、让人"听得进去"。
2. **传播设计**：怎么让活动内容的传播变成"用户喜闻乐见的内容"，并**吸引报名**。

→ 这两点都不是"排版"问题，而是"内容有效性"问题。工具的价值应体现在**帮助判断传播点与报名转化**，而非只把稿子写长。

## 5. 需求重排（以"使用频率 × 可交付性"为准）

综合官方 P0/P1/P2、口头兜底优先级与真实链路，建议按三层理解需求：

### 第一层：单次活动的内容工厂（对应 P0）

输入一份活动方案/资料 → 输出：

1. 公众号招募推文 / 回顾推文（完整可发布）
2. 小红书笔记正文 + 标题 + 话题标签
3. 3:4 活动海报 / 小红书封面
4. 社群与朋友圈转发话术（短、可直接粘贴）
5. 学生版 / 公众版 / 新闻稿三种受众改写

判断依据：这五项覆盖了"项目招募 → 活动回顾"的每一次循环，是**每场活动必走**的路径；也是文档 P0 的全部内容。

### 第二层：成套视觉与视频（对应 P1）

- 小红书多图笔记自动拆页（封面页 + 正文页 + 行动页，5–7 张）
- 1 分钟内视频脚本（分镜、时长、画面、字幕）+ 选题推荐
- 现有素材的自动字幕、BGM、封面
- PPT 生成与**可编辑**模板

判断依据：价值高但技术分叉明显（生成图 / 剪辑 / 可编辑 PPT 是四种能力），应逐项验证而非打包承诺。

### 第三层：内容体系与运营（对应 P2）

科普栏目化选题、品牌素材与模板库、内容审核与效果跟踪。属于"做成之后才有意义"的能力。

### 贯穿三层的地基（本轮新增，官方未单列但必须做）

**机构内容底座**：品牌视觉规范 + 文案撰写规范 + 历史推文 + 活动素材 + 项目与活动事实，能被工具直接读取，而不是每次人工贴进去。

依据：郎鹏"数据都在飞书，但没能建立数据库接入智能体，每次任务都要单独提供信息"——这正是地基缺失的直接描述。

## 6. 关键判断

1. **这不是"写作工具"需求，是"内容资产可复用"需求。** 同一个活动事实要被重组成公众号、小红书、话术、海报、脚本五种形态，机构要的是"一次输入、多处输出"。
2. **落点应优先在飞书内。** 机构全员用飞书办公、数据在飞书、明确表态飞书优先；脱离飞书的独立系统会额外增加一次"搬数据"的动作，正好撞在他们现有痛点上。
3. **视觉产出是不可回避的硬需求，且可能是时间受限时的第一优先。** 官方 P0 含 3:4 海报与封面，口头兜底方案更把"海报 + 小红书封面"排在最前。
4. **"真实、不虚构"是硬约束，不是加分项。** 文档要求不虚构人物故事、活动场景、数据与反馈；机构自述明确"文字核对、内容发布必须人工"。生成能力必须围绕"可核对"设计，而不是追求全自动。
5. **视频不应作为 MVP 承诺。** 需求文档外部版本列 P1，但其内部沟通稿里已把"1 分钟视频生成"划掉；陈诗瑶的回答是"C 最好，不行就 A/B"。合理定位是：先做脚本（低成本、可验证），成片作为后续。

## 7. 仍待确认与风险

| # | 事项 | 现状 | 影响 | 建议问法 |
|---|---|---|---|---|
| 1 | 全职人数、新媒体实际人力配置 | 仍无答复 | 决定"给几个人用"与上手成本上限 | 目前内容相关实际投入几个人？是否只有诗瑶老师一人？ |
| 2 | 时间受限时的第一优先：文案还是视觉 | 文档 P0 文案在前；口头答复视觉优先 | 直接决定 MVP 范围 | 如果四周只能交付一件事，是先要"能出稿"还是先要"能出图"？ |
| 3 | AI 使用与数据出域边界 | 未明确 | 决定能否调用外部模型、素材能否上传 | 活动照片、学员姓名/学校、访谈内容，哪些不能进外部工具？ |
| 4 | 素材授权流程 | 未明确 | 决定素材库能否自动入库 | 照片与人物故事对外发布是否需要本人授权？记录在哪？ |
| 5 | 品牌规范的可机读程度 | 已给 PDF，未确认是否有结构化色值/字体文件 | 决定生成的一致性上限 | 是否能提供 Logo 源文件、标准色值、字体文件？ |
| 6 | 公众号排版的技术接口 | 未讨论 | 若需"直接发布"则涉及公众号后台能力 | 发布环节是否必须人工？是否接受"生成后手动粘贴进后台"？ |
| 7 | 火山引擎账号与调用方式 | 只确认"可用" | 决定开发期能否真跑通 | 公益计划的模型如何接入？是否有配额或申请流程？ |
| 8 | 验收标准 | 只给了两份规范 + 参考账号 | 影响"做到什么程度算合格" | 有没有"发出去觉得不行"的反面案例？ |
| 9 | 小红书两个号的分工 | 只给了两个链接 | 决定一次生成要出几版 | 机构号与活动号的内容差异是什么？ |
| 10 | 活动方案的实际形态 | 未拿到样例 | 决定"输入"的解析难度 | 能否给一份真实活动方案 + 对应发布的成品？ |

**风险提示**

- **输入不规范风险**：若活动方案是自由文本且格式各异，"自动提取活动名称/亮点/时间/地点/报名信息"的准确率会显著下降，需要模板化输入或人工校正位。
- **平台合规风险**：公益机构对外内容涉及金额、人数、备案号，一旦模型改写数字即构成披露风险，必须锁定事实字段。
- **单点人力风险**：新媒体实际只有 1 人，工具若需要专门学习，落地概率低；应默认"打开就能用"。

## 8. 交付建议与下一步

**MVP 建议（待组内确认）**

以"一场活动 → 一组成品"为最小闭环，输入结构化活动资料，输出：公众号推文 + 小红书笔记 + 3:4 海报/封面 + 社群话术；附带两份规范作为生成约束，人工审核后自行发布。

**需组内拍板的两件事**

1. **MVP 切法**：文案优先（P0 原序，产出可直接发布的长文）还是视觉优先（口头兜底，产出海报与封面，演示效果更强）。
2. **承载形态**：飞书工作流 / 飞书多维表格 + AI 字段 / 内部网页工作台。三者交付成本与机构可维护性差别很大，需结合"飞书优先"表态做取舍。

**下一步动作**

| 动作 | 说明 |
|---|---|
| 索取一份真实活动方案 + 对应发布成品 | 验证输入解析与输出对齐的可行性 |
| 索取 Logo 源文件、标准色值、字体 | 海报与封面能否"像 C公益"的前提 |
| 明确 AI 数据边界 | 决定素材能否入库、能否调外部模型 |
| 用两份规范做评测基线 | 把"合格"变成可检查的条目，而不是主观判断 |
