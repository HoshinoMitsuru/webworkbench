## 一、一句话说清

给 C公益 做一个**只给内部工作人员用**的单页内容工作台：输入一份活动资料，一次产出公众号推文、小红书笔记、3:4 海报/封面、社群话术；飞书负责存资料，人负责核对和发布。

**交付物**：一个能打开、能点的网页链接 + 一页说明书。

## 二、需求基线（来自机构，可直接引用）

### 2.1 他们的真实链路【机构确认】

```
项目部：写活动方案 → 设报名表单 → 写招募推文（含报名链接）→ 招募学员
      → 开展活动 → 志愿者拍照 → 整理照片与文稿 → 写回顾推文
新媒体部：内容审核 → 制作发布
      ├─ 公众号（最常用）
      ├─ 小红书（按需，两个号：机构号 / 活动号）
      └─ 素材留存 → 后续剪视频
```

### 2.2 三条最关键的原话

| 谁 | 原话 | 对我们的意义 |
|---|---|---|
| 郎鹏 | "数据都在飞书，但没能建立起数据库接入智能体，所以每次任务都要单独提供信息，互动的过程其实是更加耗时。" | 这是最核心的痛点：缺的是**内容底座**，不是又一个写作工具 |
| 郎鹏 | "如果可以优先搭载在飞书就搭载在飞书；飞书受限就采取内部网页工作台。" | 形态可以落网页，但要为飞书留接口 |
| 陈诗瑶 | "受时间限制的话，可优先完成海报、小红书笔记封面生成这个方向。" | 时间紧时视觉优先，与文档 P0 的文案优先次序不同 |

### 2.3 量化偏好【机构确认】

- 工具集成度 **8/10**、AI 自动化 **9/10** → 一个入口、自动推进、人只审核
- AI 自动做：文案、海报、图片、活动方案提议
- 人必须做：完整活动策划、内容发布、文字核对
- 模型与费用：**火山引擎公益计划，所有模型可用**，成本不构成约束

### 2.4 官方优先级（需求文档原文）

| 级别 | 内容 |
|---|---|
| P0 | 公众号招募/回顾推文｜小红书笔记及标题｜社群与朋友圈话术｜3:4 海报与封面｜学生/公众/新闻稿转换 |
| P1 | 小红书多图拆页｜1 分钟内视频脚本｜字幕 BGM 封面｜PPT 生成与可编辑模板 |
| P2 | 科普栏目化选题｜素材模板库｜内容审核与效果跟踪 |

## 三、产品定义与范围

### 3.1 已定的三个决策

| 决策 | 结论 | 状态 |
|---|---|---|
| 形态 | 单页 Web 工作台（可点链接），不做 Trae 插件、不做原生 App | 已定 |
| 访问 | 仅机构内部人员，必须登录；不对外、不宣传、不开放注册 | 已定 |
| 用量 | 不设硬上限；异常时提醒 + 降速，不阻断 | 已定 |

### 3.2 范围

**MVP 必做**

1. 活动资料输入（表单 + 粘贴方案文本）
2. 公众号招募/回顾推文
3. 小红书笔记（标题 + 正文 + 标签）
4. 3:4 海报 / 封面（模板渲染出图）
5. 社群与朋友圈话术
6. 学生版 / 公众版 / 新闻稿三版改写
7. 分块重写（只改一段，不清空其它）
8. 导出（复制、下载 PNG、可选写回飞书文档）

**二期**：小红书多图拆页、视频脚本、多套模板。

**不做**：视频成片、可编辑 PPT、自动发布到平台后台、账号体系与协作审批。

### 3.3 时间紧时的取舍

按陈诗瑶的兜底口径：若排期不足，**优先保证"海报 + 小红书封面"能出图**，文案可用更简单的模板。理由是视觉演示效果强、且是他们最高频的实际动作。

## 四、交互骨架

三栏，对齐培训给的"内容生产工作台"：

| 区域 | 内容 |
|---|---|
| 左栏 | 三个入口：文案 / 海报 / 脚本（切换不丢已填资料） |
| 中栏 | 活动资料表单 → 选平台与受众 → 生成（有进度、可中止、可重试） |
| 右栏 | 结果分区展示；每块可"重写 / 更口语 / 更正式"；复制或下载 |

**四条硬要求**

- 不注册，登录后直接进工作台
- 首屏 3 秒可交互
- 每个结果块可单独重写
- 页面常驻"AI 生成，发布前需人工核对"

## 五、技术实现

### 5.1 架构

```
浏览器 React 单页
   │ HTTPS
   ▼
服务端（Next.js API / 云函数）  ← API Key 只在这里
   ├─ 资料结构化 + 字段校验
   ├─ Prompt 组装：品牌文案规范 + 项目线语料 + 用户输入
   ├─ 模型调用：火山引擎方舟（OpenAI 兼容）
   ├─ 事实校验：数字/时间/地点回查输入，不一致标红
   ├─ 海报渲染：HTML 模板 + satori/resvg → PNG
   └─ 返回结果（默认不落库）
```

### 5.2 四个关键技术判断

1. **海报走模板渲染，不走文生图。** 文生图中文会糊、Logo 变形、品牌色不准，机构不敢直接发。图像生成只做背景素材。
2. **API Key 绝不进前端。** 所有模型调用经服务端。
3. **默认脱敏。** 姓名、学校、电话在进 Prompt 前替换为占位符，成稿后人工填回。
4. **只用境内模型。** 避免个人信息出境，也契合火山引擎公益计划。

### 5.3 内容质量的三道闸

| 闸 | 做什么 |
|---|---|
| 事实锚定 | 生成前把活动名/时间/地点/主办方作为锁定字段，模型不得改写数字与专有名词 |
| 规范约束 | 把《C公益文案撰写规范》《品牌视觉对外露出使用规范》作为系统指令与后置检查项 |
| 人工核对 | 结果区高亮所有事实字段，提示逐项确认；不提供"一键发布" |

## 六、安全与合规红线（六条，不可让步）

1. **不做成公开服务**：必须登录、无公开注册、`noindex`。否则可能被认定为"向境内公众提供生成式 AI 服务"，触发安全评估与算法备案，我们做不了。
2. **只用境内模型**，活动资料与个人信息不出境。
3. **个人信息不进模型**：姓名、学校、联系方式默认脱敏；上传前勾选"已获授权"。
4. **不长期留存**：上传文件请求结束即丢弃，缓存不超过 24 小时，提供"一键清除"。
5. **AI 内容要标识**：图片导出带轻量标识与元数据，文本结果区标注"AI 生成，需人工核对"。
6. **儿童素材单独处理**：涉及不满 14 周岁（亲子活动）的素材，须监护人口头/书面同意后才可使用。

## 八、验收标准

用**一份真实活动资料**现场跑一遍，满足以下全部即算通过：

- [ ] 推文的事实字段（时间、地点、对象、报名方式）与输入完全一致，无编造
- [ ] 小红书笔记有标题、正文、标签，风格像大学生内容而非公文
- [ ] 海报出图 ≥1080×1440，Logo 不变形、文字不糊、品牌色正确
- [ ] 社群话术 ≤120 字，可直接复制粘贴
- [ ] 学生版/公众版/新闻稿版差异明显，不是简单缩扩
- [ ] 任一结果块可单独重写，不影响其它块
- [ ] 未登录无法访问；页面无任何 API Key 痕迹
