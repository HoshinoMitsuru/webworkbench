## 0. 一句话结论

C公益 是一家全职 7–13 人、靠 70+ 无薪志愿者运转的西北青年教育公益机构，**每月开展 20–30 场线下活动**，每场都要产出招募推文、回顾稿、海报与短视频，而**专门负责排版的志愿者只有 1 个岗位名额**。内容生产的瓶颈不在"没想法"，而在"**同一套内容模板反复从零写、且高度依赖少数志愿者**"。因此「内容生产」方向应聚焦：**把重复性内容（活动招募、活动回顾、月报、多平台改写）变成机构自己可复用的生成流程**，而不是做一个通用的写作工具。

## 3. 内容生产链现状（本文档的核心）

### 3.1 已确证的流程痕迹

从多篇推文尾部署名可以反推出固定分工：

| 推文 | 署名 |
|---|---|
| 青桥计划招募（第 28 期） | 文案 \| 张蕾　排版 \| 张粤 |
| 2026 年 10 月核心团队志愿者招募 | 文案 \| C公益　排版 \| 彩霞 |
| 项目运营实习生招募 | 文案 \| 李瑞婷　排版 \| 王芮玥 |
| 10 月月报 | （署名制，长文汇总型） |

【确证】结论：**内容产出 = 文案 1 人 + 排版 1 人**，且署名者是**轮换的志愿者/实习生**，不是全职团队。全职 7–13 人里没有专职新媒体。

### 3.2 2026 年 10 月志愿者招募岗位（决定性证据）

该招募公告直接把内容生产的岗位缺口写出来了【确证】：

| 岗位 | 名额 | 职责要点 | 工具要求 |
|---|---|---|---|
| **新媒体排版专员** | **1 人** | "完成排版任务并配合发布"（职责仅此一句，说明岗位高度流程化） | 公众号后台、**135 / 秀米**、做图（**可画**加分） |
| 品牌营销 · 小红书创作方向 | 2 人 | 撰写小红书笔记、活动故事、项目介绍；做封面、配图、海报 | Canva、醒图 |
| 活动执行 | 2 人 | 活动全流程，含"与机构其他部门协作完成活动前中后期的宣传推广" | Office、PS 优先 |
| 合作发展 / HR / 青桥项目专员 | 各 1–2 人 | — | — |

三条硬信息：
1. **排版是单点岗位，只给 1 个名额**，一旦该志愿者断档，整条发布链停摆。
2. 全部岗位**无财务报酬**，每周投入 8–15 小时，要求"持续参与半年以上"——**高流动、低冗余**。
3. 工具栈是 **135 / 秀米 / 可画 / Canva / 醒图**，即"手工排版 + 手工做图"，没有模板系统、没有生成式工具。

### 3.3 内容类型与产出强度（推断链）

| 内容类型 | 触发频率 | 单篇工作量 | 证据强度 |
|---|---|---|---|
| 活动招募推文 | 按活动计，10 月单月 27 场（含主理人自组织的小型活动，不一定每场都发） | 中—高，青桥类招募推文长达数千字 | 【确证】场次；【推断】每场是否成文 |
| 活动回顾 / 单场报道 | 同上 | 中 | 【推断】月报中逐场描述可佐证 |
| 月度月报 | 每月 1 篇 | **极高**：需跨 4 个产品线汇总 27 场活动、机构动态、受益人故事、财务披露 | 【确证】10 月月报原文 |
| 受益人故事 | 每月 1 篇左右 | 高（需采访 + 采写 + 授权） | 【确证】月报含"受益人故事"栏目 |
| 志愿者 / 实习生 / 全职招募 | 不定期，10 月连发 2 版 | 中（内容高度重复，每次重写） | 【确证】— |
| 筹款与捐赠人沟通（义拍会、月捐大使） | 年度 + 月度 | 高 | 【确证】— |
| 多平台改写（公众号 → 小红书） | 每篇主内容 | 中 | 【确证】设小红书专岗 |
| 主理人月刊 | 每月 1 期 | 中：把当月几十场活动按"活动名｜主理人｜时间｜人数｜坐标｜细节"逐条整理 | 【确证】2026-11-09 十月刊 |
| 小红书笔记 | 现状低，可见笔记以招募/招聘海报为主 | 低—中：图文海报，非生活流照片 | 【确证】搜索页截图仅见 2 条 |
| **等待期维系内容**（报名后到项目开始前） | 每个匹配型项目批次 1–2 次 | 低，但基本没人做 | 【推断】同类项目蓝信封官方明示配对等待 30–60 天，需专门建社群维持 |

**月度内容负载估算**【推断，需核实】：以 10 月为例，1 篇月报（跨 27 场活动）+ 若干活动招募 + 1 篇受益人故事 + 2 版招募公告 + 小红书笔记若干，落在 **1 名文案志愿者 + 1 名排版志愿者**身上，人均每周可用 8–15 小时。这是明显的**产能赤字**。

## 4. 痛点假设（分级，供访谈验证）

按"证据强度"排序，访谈时逐条打勾或推翻。

| # | 痛点假设 | 证据强度 | 验证方式 |
|---|---|---|---|
| P1 | **排版是瓶颈**：内容写完后卡在排版，1 个岗位、需熟练 135/秀米，志愿者上手慢 | 高【确证设岗】 | 问郎鹏：一篇推文从定稿到发布平均几天？卡在哪一步？ |
| P2 | **重复劳动**：招募公告、活动回顾、月报每月/每场重写，结构与话术高度相似 | 高【推断+文本比对】 | 问：有没有可复用的模板或 SOP？现在存在哪？ |
| P3 | **素材采集断点**：现场照片/学员反馈散落在活动执行志愿者手里，写稿时要挨个要 | 中【推断】 | 问：写一篇回顾稿，找素材要花多久？素材存在哪（群/网盘/表格）？ |
| P4 | **多平台分身**：同一场活动要出公众号长文 + 小红书笔记 + 短视频脚本，各自重写 | 高【确证设小红书岗 + 两个号在运营但笔记少】 | 问：小红书是从公众号改的，还是重写？两个号怎么分工？谁做？ |
| P5 | **志愿者流动导致质量不稳**：新人不懂机构调性，反复返工 | 中【推断】 | 问：新志愿者从接手到能独立出稿要多久？返工率？ |
| P6 | **月报是集中式灾难**：月底要从各项目捞信息，跨人跨表汇总 | 中【确证月报形态】 | 问：月报是谁写？素材怎么收？花几天？ |
| P7 | **数据/成果难量化呈现**：620 场、6 万人次这类数字分散，写稿时要重新统计 | 低—中【推断】 | 问：有没有统一的活动数据台账？ |
| **P8** | **等待期内容真空**：匹配型项目（青桥计划）从报名到匹配成功之间有一段空档，期间几乎没有内容维系，学员容易遗忘或流失 | 中【外部类推】 | 问：青桥从报名到匹配多久？等待期发内容吗？报名后未出席率多少？ |
| **P9** | **素材只用一次**：照片、参与者原话、活动数据只在活动后汇总一次，随后散落，导致"公益科普 / 青年故事 / 活动反馈"三类长尾内容没有稳定供给 —— 而这正是机构提的小红书增长点 | 中高【确证十月刊结构 + 机构自述】 | 问：一场活动的照片、反馈、数据，活动结束后存在哪？之后还会被用第二次吗？ |

> **P8 的由来**（重要，写进需求文档时要说清这是一手经验而非臆测）：本组成员张雨彻曾担任蓝信封（留守儿童书信陪伴项目）通信大使。蓝信封官方口径是"审核通过后平均需等待 30–60 天匹配合适笔友，寒暑假暂停配对"，因此机构必须额外建立"小信子"咨询账号与通信通知群来维持志愿者热情。C公益 的青桥计划同样是**一对匹配型**项目（报名 → 匹配职场导师 → 1v1 沟通），结构相似，故提出该假设，**待 B7 问题验证**。
>
> 若 P8 成立，它会给「内容生产」方向增加一个别人想不到的品类：**进度型内容**（"你的申请到哪一步了""还要等多久""匹配上之后会发生什么"）。这类内容不需要创意，只需要模板与数据，恰好最适合 AI 生成。

**暂不下结论、但需警惕的反向可能**：
- 也许机构真正缺的不是"写得快"，而是"**没人写**"（产能=人力，不是效率）。若如此，AI 生成反而是正解——把 1 人当 3 人用。
- 也许机构对内容质量的要求很高（受益人故事需要真实细节），AI 生成反而不适用，应聚焦"**结构化初稿 + 人工润色**"的辅助位。

## 5. 目标用户画像

需求文档要求写清"给机构中哪类角色用"，按优先级排：

### 主用户：内容/品牌志愿者（排版专员、小红书创作方向）
- 身份：在校大学生，线上协作，无薪，每周 8–15 小时，任期常 3–6 个月
- 技能：会用 135/秀米/可画，文字功底一般，**不熟悉机构历史与项目术语**
- 核心诉求：**拿到一个"填几个空就能出稿"的入口**，不用读懂 13 年机构史
- 失败场景：新人不了解"攒劲青年 vs 青桥计划"的区别，写出串味的稿子

### 次用户：项目专员 / 项目负责人（如郎鹏）
- 身份：全职 7–13 人之一，同时管多个项目
- 核心诉求：**快速把一场活动的信息变成可发布的内容**，且不用自己动手排版
- 失败场景：活动结束当晚要在群里催稿，等两天才发出去，热度过了

### 第三用户：捐赠人 / 合作方沟通岗（筹款线）
- 核心诉求：月报、义拍会材料、月捐大使招募的**规范化产出**，数据不能错
- 失败场景：数字口径不一（600 场 vs 620 场），对外披露出风险

### 候选 A：活动内容一键成稿（推荐做 MVP）
- **场景**：项目专员在活动前后填入"活动名称 / 项目线 / 时间地点 / 参与人数 / 3 个亮点 / 现场照片"，系统输出 ①公众号招募或回顾长文 ②小红书·青年故事 ③小红书·活动反馈 ④公益科普短图文 ⑤海报文案
- **价值**：直接命中 P1 P2 P3 P4 P9，10 月 27 场活动的量级足以摊薄使用成本；三类小红书内容（科普/故事/反馈）是同一份活动输入的不同切法，不需要另起生产线
- **可行性**：高。输入可结构化（表单/多维表格），输出是文本 + 固定版式；素材入库前加"是否可公开"字段，未授权的不进生成环节
- **风险**：不同项目线（攒劲青年/青桥/志夏）话术差异大，需要"机构知识库"约束调性

### 候选 B：月报自动汇总
- **场景**：各项目把活动记录写进统一多维表格，月底一键生成月报初稿（分板块、含数据统计）
- **价值**：命中 P6 P7，单次节省的人力最大
- **可行性**：中。**前置条件是机构愿意把活动记录结构化**——这是流程改造，不是工具问题
- **风险**：机构现有记录可能散在微信群和文档里，迁移成本高

### 候选 C：受益人故事采写助手
- **场景**：把访谈录音/聊天记录转成故事稿
- **价值**：内容质量最高、最能打动捐赠人
- **可行性**：低。素材非结构化、涉及隐私授权、AI 生成易失真
- **结论**：不建议作为 MVP

**推荐组合**：MVP 做 **候选 A**，把"机构知识库 + 三个项目线的话术模板"作为底座；候选 B 作为二期（若机构愿意先做活动记录结构化，则 B 的价值高于 A）。

**交付物（按培训标准）**：一个能打开、能点的产品链接 + 一页说明书（解决什么、怎么用、边界在哪）。第一阶段只跑通"素材进库 → 生成公众号 + 小红书两版 → 人工审"，效果复盘、界面美化放到二期。

**若 P8 成立，追加一个低成本扩展**：在候选 A 里加一个「进度通知」模板族（报名成功 / 审核通过 / 还在排队、预计还要多久 / 匹配成功、接下来做什么）。它技术上最简单（纯模板 + 变量），但正好补上现有内容的空白段，且能直接用"减少流失"来讲价值——**对筹款和捐赠人沟通是加分项**。

> 与培训给的官方「内容生产工作台」形态对齐：左侧三入口（文案生成 / 海报生成 / 脚本生成）、中间"输入主题与目标人群 → 生成初稿"、右侧短视频脚本（镜头/画面/旁白）+ 机构修改区（项目背景/传播重点/行动号召）。候选 A 正好覆盖这个骨架的三分之二，海报与脚本可作为加分项。

## 7. 给郎鹏的访谈提纲（对谈可用，2026-11 更新）

按 25–30 分钟设计，先问事实、再问痛点、最后问限制。**不要一上来就问"你想要什么功能"**。

### 第一组：确认事实（5 分钟）
1. 目前机构全职几人？其中谁负责对外内容？有没有专职新媒体？
2. 公众号「攒劲青年」和旧号「C公益活动种草中心」现在多久发一篇？最近一个月发了几篇，分别是什么类型？
3. 一篇推文从有想法到发布，平均走几天？谁定稿？

### 第二组：拆流程（10 分钟）
4. 上个月那 27 场活动，是不是每场都要出推文？还是只挑重点场次？挑的标准是什么？
5. 一篇活动回顾稿，素材（照片、学员反馈、数据）从哪里来？找素材要花多久？
6. 排版现在是谁在做？如果他这周没空，稿子会怎样？
7. 小红书的内容是公众号改写还是重写？视频号/短视频谁做？
8. 月报是谁写？各项目的信息怎么汇总到你这里？

**第二组补充：账号矩阵（3 分钟，11-18 新增）**

8a. 公众号「攒劲青年」和「C公益活动种草中心」现在是什么关系？以后以哪个为准？
8b. 小红书两个号分别谁在维护？「来自西北的小C同学」还在用吗？
8c. 小红书现在一个月发几条？最近一条是什么时候？从想到发要几天？
8d. 一条笔记的封面和配图谁做？用模板，还是每次新画？

### 第三组：痛点排序（5 分钟）
9. 这条链上最耗时间的是哪一步？（请排序：想选题 / 写文案 / 找素材 / 排版 / 做图 / 多平台改写 / 汇总月报）
10. 有没有出现过"活动做了但没发出来"的情况？大概占比多少？
11. 新来的志愿者，多久能独立出一篇合格的稿子？常犯什么错？

### 第四组：限制条件（5 分钟）
12. 机构有没有内容预算（外包设计、买工具、投流）？大概量级？
13. 除了你，谁还能长期维护这个工具？如果我们交付一个网页应用，后续谁来用、谁来管？
14. 机构现在用什么协作（飞书？微信？）数据都存在哪？我们做的工具能不能接进去？
15. 有没有对外披露的合规要求（慈善组织信息公开、募捐备案），内容里哪些话不能说？
15a. 机构对 AI 工具的使用有什么规定？哪些能用、哪些明确禁用？有没有黑白名单？
15b. 活动照片、学员姓名/学校、聊天记录，哪些不能出机构或上传到外部工具？照片对外发布要本人同意吗？

### 第五组：成功标准（3 分钟）
16. 如果四周后我们交付的东西真的有用，你会怎么判断它有用？（例如：一篇稿子从 3 天变 1 天 / 排版不用等人 / 月报半天搞定）
17. 有没有现成的"好稿子"样本，可以给我们 2–3 篇当标杆？
17a. 有没有发出去以后觉得"不行"的稿子？也给我们两三篇——正反样本都要，才知道什么不能写。
17b. 这四周里，有哪些是明确不希望我们碰的？

**收尾要一句**：这次我们只做一件事，你希望是哪一件？（逼出优先级，避免需求发散）

## 8. 技术条件限制（影响方案设计）

| 限制 | 现状 | 对方案的影响 |
|---|---|---|
| 无技术团队 | 全职 7–13 人，均为项目/运营背景，无开发 | 方案必须是**零代码、可视化配置**，不能要求维护服务器 |
| 无内容预算 | 志愿者无薪；未见设计外包预算 | 不能选付费 API 依赖重的方案，优先用机构已有的免费额度 |
| 人力极薄 | 1 名排版 + 2 名小红书 + 轮换文案 | 上手成本必须极低，**不能让用户先学一套新系统** |
| 工具栈既定 | 135 / 秀米 / 可画 / Canva / 醒图 / 飞书 | 输出要能直接进 135 或秀米，否则等于多一道工序 |
| 协作在线化 | 志愿者分布 7 国 26 城，全线上协作 | 工具必须**云端可用、多人可访问**，不能是本地程序 |
| 合规约束 | 慈善组织信息公开、公开募捐备案 | 生成内容涉及金额、人数、备案号时必须锁定事实，不能让模型编 |
| AI 使用边界 | 【未知】是否禁用某些工具、数据能否出机构/上公有云 | 必须先问清；方案只能跑在机构允许的工具内 |
| 素材授权 | 【未知】照片、学员信息的对外授权流程 | 素材库只进"已授权、可公开"的素材，未标注的不进生成环节 |
| 品牌调性 | 13 年积累，语气偏"朋辈、温暖、不居高临下" | 需要机构语料库约束，否则生成稿会"AI 味" |

## 9. 待你拍板的分岔

这三件事我不替你定，需要你和组内确认：

1. **产品形态**：网页应用（WorkBuddy/Vibe Coding）/ 扣子智能体 / 飞书多维表格 + AI 字段。三者交付成本与机构可维护性差别很大。
2. **MVP 范围**：只做"活动成稿"，还是连海报与短视频脚本一起做。做多容易烂尾，做少可能不够亮眼。
3. **知识库来源**：机构语料从哪来（历史推文 620 场活动的存档 / 官网文案 / 郎鹏口述），这决定生成质量的上限。
