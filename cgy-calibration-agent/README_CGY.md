## 1. 为什么拿这个引擎来适配

原引擎解决的问题（死循环、乱调工具、调用无界、一挂就崩、出事查不到）恰好是公益机构用 AI 工具最怕的五件事——机构没有技术团队，工具必须**自己会停、自己会降级、出错能查**。而它的业务层（泛自媒体规则）与 C公益 的真实痛点错位，所以本次适配**只换业务面，护栏一行不动**：

| 层 | 原引擎 | C公益 适配 | 改动方式 |
|---|---|---|---|
| 控制器/循环守卫/工具白名单/降级骨架/可观测 | 10 终止态 + 7 闸门 | **原样继承** | 零改动（12 个核心文件哈希与源一致） |
| 业务规则 | R1–R4（互动率/粉丝/曝光/兜底） | 继承 R1/R3/R4 + 新增 **G1–G7 公益规则** | 新增 `domain_cgy.py` |
| 平台适配 | devto/hashnode CLI 模板 | **机构账号矩阵**：公众号双号 + 小红书双号 + 活动台账 + 匹配队列 | 新增 `platforms_cgy.py` |
| 提示词 | 泛内容校准师 | 公益校准师：朋辈调性 + **合规红线 10 条** | 新增 `prompts_cgy.py`（原文件不动，版本化） |
| 场景/装配 | 4 场景 | 原 4 场景对应版 + **合规拦截场景** | 新增 `factory_cgy.py` |
| 入口 | `main.py` | 增 `--profile cgy`（原用法完全兼容） | 增量修改 |

## 2. G1–G7 公益规则（每条带依据与阈值出处）

| 规则 | 判定 | 阈值（全部为预研假设，待对谈校准） | 依据 | 指向 |
|---|---|---|---|---|
| G0 继承体检 | 互动率 <2%（原始值）、有曝光无点赞、缺字段出「未获取」卡 | 沿用原 R1/R3 口径 | 原引擎三条不变量 | — |
| G1 矩阵分工 | 旧号当月仍发新内容 → 权重分散；未知账号 → 不做判断 | 旧号发文 ≥1 篇 | 官网调研 W6；双号并行确证 | D1 两号版本 |
| G2 产能缺口 | 月发文 < 台账场次 × 30% | 30%（假设约 1/3 场次值得成文） | P1/P2；10 月 27 场 vs 推文量级 | **D1 归档生成** |
| G3 素材复用 | 小红书科普/故事/反馈占比 <50% | 50% | P9；增长点文档「一次归档三种切法」 | **D1 三切法** |
| G4 等待期 | 青桥排队 >14 天且未发进度通知 | 14 天（蓝信封经验类推，**P8 待验证**） | 画像文档 §4 P8 | **D3 进度信** |
| G5 合规红线 | 建议文案命中红线词（返利/绝对化/伪公募表述）→ P1 拦截卡 | 词表 6 条 | 慈善信息披露 + 募捐备案约束 | 人工复核；备案名「打破资源鸿沟 点亮西北未来」 |
| G6 品牌落地 | 内容标记 legacy 版式 → 品牌 3.0 未落地 | ≥1 篇 | 官网调研 W2 | D1 海报规范 |
| G7 全局兜底 | 全部 0 卡才补 1 张「数据不足」 | 继承原 R4 语义 | 不硬造结论 | 对谈补数据 |

**三条不变量原样继承**：① 判定用原始值（0.019975<2% 必须触发，展示值 0.02 不得冒充）；② 缺字段不补 0、不推断（「小C同学」演示号故意缺数据）；③ 扩展字段原样透传。

## 4. 与 D1–D3 打样的闭环

```
活动结束 → D1 归档一行（= 本引擎台账数据源，字段同源）
              ↓
本引擎每月跑一轮 → 校准动作卡（哪条产能缺口/哪类素材没复用/谁在等待期失联）
              ↓
卡上的 action 指回工具位：G2→D1 生成五路 / G3→D1 三切法 / G4→D3 进度信 / 月报→D2
```

对谈时一句话讲清：**D1–D3 是「手」，这个引擎是「眼睛」**——手负责把内容做出来，眼睛负责告诉机构下一步该做哪件、哪件没做。

## 5. 真实接入路径（机构零代码）

1. **数据**：机构从公众号/小红书创作者中心导出 → 填一份 JSON（结构见 `platforms_cgy.JSONCgyAdapter` 注释）→ `python main.py --profile cgy --cgy-data 机构数据.json`。只读机构自己导出的文件，不抓取、不联网、不碰平台凭据。
2. **模型**：按原引擎 `config.example.yaml` 接 OpenAI 兼容接口（`provider: openai`，key 只走环境变量）。当前 Mock 演示不消耗任何 token。
3. **阈值校准**：对谈确认「挑重点场次的标准」「真实匹配周期」「三类内容目标占比」后，改 `domain_cgy.py` 顶部注释标明的三个假设阈值即可，护栏零改动。
